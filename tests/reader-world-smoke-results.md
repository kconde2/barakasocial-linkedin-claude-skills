# Shared reader context: behavioral checks

These trials use isolated synthetic authors and temporary files. No real personal profile, account, network research, paid analysis or LinkedIn action is used. Results below record observed agent behavior, not guaranteed compliance or proof of better engagement. This is not an automated model benchmark.

## Distribution

The archive tests first failed when the new schema resource was expected but absent. After implementation, all 4 tests passed across the 5 skills, including exact packaged bytes, reproducibility and identical shared resources. The schema is packaged with every skill, not a dependency on another installed skill.

## Trials

The following results were read and checked by the root agent, including the actual saved files.

### Guided discovery, author reply, writing and accepted save

A dedicated agent read the actual Topic Finder and shared personalization. Its only author context was synthetic available memory: Nora, accessibility consultant addressing small agency owners, simple voice, wanting to demonstrate judgment without routinely selling, and a previously stated view about automated checks versus keyboard testing.

First user turn: no topic, request 2 useful subjects to share with a project manager and help define reusable context.

Observed: proposed SV-001 about what remains to check at the keyboard and SV-002 about framing a test request. Marked the second subject as a hypothesis about reader needs. Recommended the first because it used an expressed viewpoint. Asked 2 relevant questions about when requests arrive and what the reader should learn to decide. No post or file was created.

Second user turn selected SV-001, reported receiving requests mainly before delivery, supplied an explicitly illustrative form (name, email, send button) and 3 keyboard checks, with no known audit result. Requested one short post and a proposal of context to retain.

Observed: read/applied the Writer and Hook Generator, wrote one post without repeating the audience/quantity questions, labeled the form as a demonstration and did not invent an audit result. The post explained the supplied checks. Proposed 6 durable context items separately and offered to save them; no write before an answer. The first offer named a dedicated private profile but not an exact path. The next user turn supplied the path explicitly, so default-path acceptance remains untested.

Third turn explicitly accepted the proposed context and named a temporary profile path. Observed: read the schema, wrote through a temporary sibling and replaced the destination, verified the JSON and reported success without another permission question. The root agent inspected the actual file. It contained author/audience/voice, expertise, goal, reader promise, one reported reader situation and one reported author perspective. The illustrative form and temporary short/share/no-commercial-CTA choices were absent from persistent fields.

### Actual persistence, replay and temporary override

A separate agent created an older version 1 fixture with unknown top-level, editorial and CTA properties. A synthetic save request supplied a durable goal, an expressed author view, a reported reader question and a hypothesized fear with no testimony. The agent applied the schema via a local test script, replayed the same request and kept a one-post humor override outside the file.

Observed: 21 assertions passed. Old properties remained intact. The question and view stayed `reported`, the emotion stayed `inferred`, each with origin and stable IDs/dates. Files after save, replay and temporary override were byte-identical. The root independently compared the files and preservation of initial fields. No real profile was used.

Limitation: the replay uses the same temporary merge function written by that agent. This tests its chosen implementation of the instructions, not a second independent language interpretation or a runtime merge service shipped by the skills. Concurrent writes and malformed profiles were not exercised.

### Independent Writer using only the saved profile

A fresh agent received the Writer path, the synthetic saved profile path and a request for a short explanation of automated scores versus keyboard testing, with no personal anecdote or CTA. It received no discovery transcript or author memory.

Observed: read the Writer, personalization, schema and saved profile, then applied the Hook Generator. Wrote one explanatory post for small agencies without further questions or file writes. It did not turn the hypothetical fear into a fact, narrate a personal incident or add a CTA. Its closing distinguished complementary checks from a complete accessibility audit. This technical explanation was not independently audited by a domain expert in this test.

## Limits and verification

These are agent-driven trials with scripted synthetic user replies, not interactions with human readers or a comparison of writing quality. They do not establish higher reach, emotional effect or sales. Native question widgets, real external memory integrations, web research, MCP, concurrent profile writes and target-client installation remain untested in this lot.

All 5 skill entrypoints passed the validator, all 5 ZIPs were rebuilt, 4 distribution tests passed and 209 local links/anchors resolved before the final result links were added. The latter links were checked separately. French punctuation and `git diff --check` passed. No commit, push, release or real user profile write occurred.
